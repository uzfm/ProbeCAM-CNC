# План ProbeCAM CNC

## Мета
Створити сучасний кросплатформний застосунок (Windows та Linux) на **PySide6**, який використовує камеру та OpenCV для точного визначення геометрії заготовки, її кута, центра отворів/контурів, автоматичного визначення робочого нуля та керування рухом ЧПУ через USB за допомогою GRBL або PI_GRBL_HAL.

Головна ідея системи: камера є вимірювальним інструментом станка. Після калібрування програма повинна знати:
- масштаб зображення в мм/піксель;
- оптичний центр/ціль камери;
- постійне зміщення між ціллю камери та віссю шпинделя;
- положення знайденого об'єкта відносно координат CNC;
- кут повороту заготовки;
- координати центра заготовки, отвору, кола, кута або іншої базової геометрії.

---

## Архітектура (важливо!)
- **Форма (UI) відділена від логіки.** Весь інтерфейс описується в окремих `.ui`-файлах (XML), які створюються та редагуються візуально в **Qt Designer**.
- **Заборонено** будувати інтерфейс вручну в коді (`QPushButton(...)`, `addWidget(...)` тощо для основних вікон/діалогів). Код відповідає лише за логіку, обробку подій та зв'язування сигналів.
- Завантаження форм:
  - динамічно через `PySide6.QtUiTools.QUiLoader`;

- UI не повинен містити математику калібрування, координатні перетворення або Vision-алгоритми.

## Ключова концепція: координатні системи

Програма повинна чітко розрізняти щонайменше чотири координатні системи:

1. **Image coordinates**
   - координати пікселів `(u, v)` у кадрі камери.

2. **Camera coordinates**
   - координати в мм відносно цілі/оптичного центра камери.

3. **Machine coordinates**
   - реальні координати станка X/Y/Z.

4. **Workpiece coordinates**
   - локальна система координат заготовки після визначення її положення та кута.

Уся логіка повинна використовувати явні перетворення між цими системами, а не розкидані по коду поправки `+offsetX`, `-offsetY`.

## 3. Overlay та ціль камери

Поверх відео повинна постійно відображатися вимірювальна ціль.

### Ціль:
- центральний хрест;
- центральна точка;
- коло навколо центра;
- можливість змінювати діаметр кола;
- відображення діаметра в мм після калібрування масштабу;
- за потреби перемикання мм / pixels.

Коло особливо потрібне для ручного центрування по отворах та круглих деталях.

### Налаштування overlay:
- довжина ліній хреста;
- товщина;
- діаметр кола;
- діаметр кола можна задавати в pixels або mm;
- кілька концентричних кіл за потреби;
- показ/приховування координат;
- показ відхилення знайденого центра від цілі:
  - `dX`
  - `dY`
  - відстань до центра.

### Програмний zoom
Вікно камери повинно підтримувати digital zoom без зміни параметрів самої камери.

Бажано:
- `1x`, `2x`, `4x`, `8x`;
- плавний zoom колесом миші;
- кнопки `Zoom +`, `Zoom -`, `Reset 1x`;
- zoom відносно цілі камери або точки під курсором;
- можливість панорамування збільшеного зображення;
- поточний коефіцієнт zoom показується на екрані.

**Критично:** усі overlay-елементи, що прив'язані до геометрії кадру, повинні масштабуватися разом із зображенням.

Наприклад:
- коло цілі задане як `Ø5.00 mm`;
- при `1x` воно займає певну кількість екранних пікселів;
- при `4x` його видимий діаметр стає у 4 рази більшим;
- його фізичне значення при цьому залишається `Ø5.00 mm`.

Так само разом із zoom повинні масштабуватися:
- хрест;
- коло цілі;
- знайдені контури;
- точки центра;
- лінії вимірювання;
- bounding boxes;
- підписи/розмірні стрілки за геометричною позицією.

Товщину ліній і розмір тексту бажано масштабувати окремо або обмежувати, щоб при великому zoom вони не ставали надмірно товстими.

Vision-алгоритми повинні працювати у координатах **оригінального кадру**, а zoom використовується тільки для відображення та точнішого ручного наведення.

## 4. Калібрування камери

Калібрування складається з кількох незалежних процедур.

### 4.1. Калібрування оптики
- Checkerboard або ChArUco.
- Визначення camera matrix.
- Distortion coefficients.
- Корекція дисторсії перед точними вимірюваннями.

### 4.2. Калібрування масштабу
Визначити перетворення:

`pixels -> mm`

Базовий варіант:
- `mm_per_pixel_x`
- `mm_per_pixel_y`

Кращий варіант:
- 2D affine/homography calibration, якщо камера не стоїть абсолютно перпендикулярно до площини заготовки.

Калібрування масштабу обов'язково прив'язується до:
- конкретної камери;
- resolution;
- focus/оптичного zoom, якщо він змінюється;
- фіксованої механічної висоти камери над робочою площиною.

У базовій конфігурації ProbeCAM камера жорстко закріплена, а відстань від камери до робочої площини не змінюється під час роботи. Тому масштаб не перераховується від координати Z і не повинен залежати від поточного положення осі Z.

Якщо механічна висота камери, об'єктив або оптичний focus/zoom були змінені — калібрування pixels/mm необхідно виконати повторно.

**Програмний (digital) zoom не змінює калібрування pixels/mm**, оскільки це лише масштаб відображення вже отриманого кадру.

---

## 5. Калібрування цілі камери

Окрема команда:

**Calibrate Camera Target**

Вона задає точний піксельний центр вимірювальної цілі.

За замовчуванням це центр кадру, але програмно повинна існувати можливість задати:

- `target_u`
- `target_v`

Це дозволить компенсувати ситуацію, коли оптична вісь або механічне кріплення камери не співпадають точно з геометричним центром кадру.

---

## 6. Калібрування Camera ↔ Spindle

Це одна з головних калібровок системи.

### Ручна процедура:
1. Встановити тонкий інструмент/голку у шпиндель.
2. Шпинделем точно поставити маленьку контрольну точку на поверхні.
3. Не змінюючи координат станка, запам'ятати положення шпинделя.
4. Перемістити станок так, щоб ця сама точка опинилась точно під ціллю камери.
5. Навести хрест/коло камери точно на контрольну точку.
6. Натиснути **Save Camera-Spindle Offset**.

Програма розраховує:

`camera_to_spindle_dx`

`camera_to_spindle_dy`

Це постійний вектор між віссю шпинделя та вимірювальною ціллю камери.

### Важливо
Калібрування має виконуватись:
- при однаковому напрямку під'їзду осей, щоб мінімізувати backlash;
- при жорстко закріпленій камері;
- на тій самій або відомій площині Z;
- повторно після механічного переміщення камери.

Бажано зробити автоматичну перевірку калібровки кількома повторними вимірами.

---

## 7. Camera position / Spindle position

У програмі повинні бути дві команди позиціонування відносно однієї вибраної точки.

### `Move Spindle To Point`
Вісь шпинделя приїжджає точно у задану координату.

### `Move Camera To Point`
Вимірювальна ціль камери приїжджає точно у цю саму координату.

Перехід виконується через збережене `camera_to_spindle` зміщення.

Наприклад, якщо робочий нуль знаходиться в `X0 Y0`:

- режим **Spindle** -> шпиндель знаходиться над `X0 Y0`;
- режим **Camera** -> камера знаходиться над `X0 Y0`, а координати станка фізично зміщені на calibration offset.

Це не повинно змінювати саму робочу нульову координату. Змінюється тільки фізична позиція каретки.

## 9. Детекція центра отвору / кола

Потрібні два режими.

### Manual assisted
Користувач приблизно наводить камеру на отвір, вибирає ROI, а OpenCV знаходить:
- коло;
- еліпс;
- контур;
- центр.

На відео показується:
- знайдений центр;
- ціль камери;
- `dX/dY` між ними.

### Automatic center
Програма:
1. знаходить центр;
2. переводить pixel offset у mm;
3. дає команду CNC на корекцію X/Y;
4. повторює детекцію;
5. завершує, коли помилка менша заданого допуску.

Це дозволяє реально автоматично центрувати камеру над отвором.

---

## 10. Визначення положення та кута заготовки

На першому етапі визначення положення заготовки має бути переважно **ручним, але з точними вимірюваннями камерою**.

Основний принцип:
- оператор пересуває камеру над потрібними місцями заготовки;
- у кожній потрібній позиції ставить/підтверджує вимірювальну точку;
- програма запам'ятовує Machine X/Y для кожної точки;
- на основі цих точок програма обчислює геометрію заготовки.

### Ручні режими
Мають бути доступні:
- поставити точку `P1`;
- поставити точку `P2`;
- за потреби `P3`, `P4`;
- побудувати лінію між двома точками;
- визначити довжину;
- визначити кут лінії відносно Machine X;
- визначити перетин двох ліній;
- визначити кут заготовки;
- визначити центр між двома або кількома точками;
- визначити габарит заготовки.

Точки бажано ставити саме після фізичного переміщення камери у потрібне місце, а не тільки кліком по великому зображенню. Це дозволяє використовувати точні координати самого CNC і не залежати від того, чи вся заготовка поміщається у поле зору камери.

### Автоматичні функції на першому етапі
Автоматизувати тільки те, де це реально дає перевагу:
- пошук центра отвору/кола;
- локальне автоматичне центрування камери над отвором;
- автоматичне визначення кута видимої прямої грані заготовки.

Інші геометричні точки на першому етапі задаються оператором вручну.

### Результат визначення кута
Якщо знайдено кут заготовки `A`, програма повинна:
- показати його на екрані;
- зберегти значення;
- дати можливість скопіювати його;
- записати його у файл параметрів для подальшого використання при створенні G-code.

**На першому етапі програма НЕ повинна автоматично трансформувати або повертати всі Machine/Work координати за цим кутом.**

Кут є виміряним параметром заготовки, який потім використовується модулем генерації G-code.

Наприклад:
```text
Workpiece angle: -1.372 deg
Zero X: 125.420 mm
Zero Y: 83.115 mm
```

## 11. Автоматичне визначення нульової точки

Це головний workflow ProbeCAM.

### Варіанти Zero Detection:
- центр отвору;
- центр кола;
- перетин двох граней;
- кут прямокутної деталі;
- центр прямокутника;
- центр знайденого контуру;
- заданий offset від знайденої геометрії;
- fiducial/reference mark.

### Типовий workflow
1. Оператор приблизно переміщує камеру до потрібної області.
2. Вибирає тип бази: Hole / Corner / Edge / Center / Fiducial.
3. Vision знаходить геометрію.
4. Програма визначає координату знайденої точки відносно цілі камери.
5. Pixel offset переводиться у mm.
6. Враховується Camera-Spindle offset.
7. Отримується точна Machine coordinate потрібної точки.
8. Користувач може:
   - встановити її як Work X0/Y0;
   - перемістити туди камеру;
   - перемістити туди шпиндель.
9. Після підтвердження програма задає робочу систему координат GRBL.

---

## 12. Збереження параметрів заготовки для G-code

На першому етапі замість автоматичної компенсації координат потрібно реалізувати збереження всіх знайдених параметрів заготовки.

Окрема кнопка, наприклад:

**Save Workpiece Parameters**

або

**Export G-code Parameters**

Після натискання у файл зберігаються актуальні параметри, які були визначені камерою та CNC.

### Мінімальний набір параметрів
- робочий нуль X;
- робочий нуль Y;
- за потреби Z;
- кут заготовки;
- центр заготовки, якщо він визначений;
- знайдені центри отворів;
- ручні точки `P1...Pn`;
- виміряні відстані;
- ширина/висота заготовки;
- дата/час;
- активний calibration profile.

Приклад:
```json
{
  "zero": {
    "x": 125.420,
    "y": 83.115
  },
  "workpiece_angle_deg": -1.372,
  "workpiece_center": {
    "x": 182.500,
    "y": 116.200
  },
  "points": {
    "P1": [125.420, 83.115],
    "P2": [245.830, 80.230]
  },
  "holes": [
    {
      "x": 150.220,
      "y": 100.115,
      "diameter": 6.02
    }
  ]
}
```

Формат на першому етапі — JSON.

Пізніше цей файл може напряму використовувати модуль генерації G-code, який уже сам вирішує, як застосовувати:
- нуль;
- зміщення;
- кут заготовки;
- координати отворів та інших базових точок.

## 13. Confidence та перевірка результату

Кожна автоматична детекція повинна повертати:
- знайдені координати;
- тип геометрії;
- confidence score;
- геометричну похибку;
- residual/error fit.

Якщо confidence нижче порога:
- нуль автоматично НЕ встановлюється;
- користувачу показується знайдений контур;
- пропонується ручне підтвердження або інший ROI.

Спочатку потрібно довести до стабільної роботи основні функції:
- камера;
- калібрування;
- Camera ↔ Spindle offset;
- zoom;

## Принципи точності

- Не використовувати сире зображення для метрології без distortion correction.
- У базовій конфігурації висота камери над робочою площиною фіксована, тому pixels/mm не залежить від поточної координати Z.
- При зміні механічної висоти камери або оптики pixels/mm калібрується повторно.
- Digital zoom не змінює метричне калібрування і не бере участі в координатних розрахунках.
- Camera ↔ Spindle offset — окрема калібровка від pixels/mm.
- Target center — окрема сутність від геометричного центра кадру.
- Backlash повинен враховуватись процедурою під'їзду.
- Автоматичне встановлення нуля тільки після перевірки confidence.
- Усі координатні перетворення повинні бути централізовані в `core/coordinates/`.

## Примітки
- Нові вимоги додавати сюди в міру розвитку проєкту.
- Код застосунку має залишатися узгодженим із цим планом.
