# План ProbeCAM CNC

## Мета
Створити сучасний кросплатформний застосунок (Windows та Linux) на **PySide6**, який використовує камеру та OpenCV для визначення країв і кута деталі, калібрування камери та керування рухом ЧПУ (CNC) через USB за допомогою GRBL або PI_GRBL_HAL.

## Архітектура (важливо!)
- **Форма (UI) відділена від логіки.** Весь інтерфейс описується в окремих `.ui`-файлах (XML), які створюються та редагуються візуально в **Qt Designer**.
- **Заборонено** будувати інтерфейс вручну в коді (`QPushButton(...)`, `addWidget(...)` тощо для основних вікон/діалогів). Код відповідає лише за логіку, обробку подій та зв'язування сигналів.
- Завантаження форм відбувається одним із двох способів:
  - **Динамічно**, через `PySide6.QtUiTools.QUiLoader` — без компіляції, зручно для швидких ітерацій з агентом;
  - **Або** через компіляцію `.ui` → `.py` утилітою `pyside6-uic`, якщо потрібна автодоповнення/типізація в IDE.
- Кожне вікно/діалог = окрема пара файлів: `window_name.ui` (форма, редагується в Designer) + `window_name.py` (логіка, клас-нащадок, що завантажує `.ui`).
- Структура проєкту (орієнтовно):
  ```
  probecam/
    ui/                 # .ui файли — редагуються в Qt Designer
      main_window.ui
      calibration_dialog.ui
      jog_panel.ui
      ...
    views/               # Python-класи, що завантажують .ui і містять лише UI-логіку
    core/                # камера, OpenCV pipeline, серійний зв'язок, калібрування
    models/              # дані профілів, калібровок, height map
    resources/           # іконки, теми, qss
    main.py
  ```
- Це гарантує: ти відкриваєш `.ui`-файл у Qt Designer і вільно редагуєш форму мишкою (переставляєш кнопки, міняєш лейаути, додаєш віджети), а агент коду редагує тільки Python-логіку, не чіпаючи форму.

## Стек технологій
- **PySide6** (Qt Widgets) — основний UI-фреймворк.
- **OpenCV (opencv-python)** — обробка зображень, детекція країв, калібрування камери.
- **pyserial** — серійний зв'язок з GRBL / PI_GRBL_HAL.
- **NumPy** — обчислення, робота з матрицями (height map, калібрування).
- **JSON** — початкове зберігання даних; **SQLite** — за потреби пізніше.
- **Qt Designer** — редагування `.ui`-файлів.
- **pytest** — модульні тести для `core/` (логіка без UI повинна бути тестованою окремо).

## Редагований Roadmap

### 1. Базовий застосунок
- Головне вікно (`main_window.ui`) з сучасною темною темою (QSS-стиль у `resources/theme.qss`).
- Панель попереднього перегляду камери з накладеннями (overlay) поверх відео.
- Статус-бар та журнал подій (event log).
- Завантаження/збереження проєктів і профілів.

### 2. Підсистема камери
- Виявлення та список доступних камер.
- Підтримка UVC-вебкамер та промислових USB-камер.
- Налаштування роздільної здатності, FPS, витримки (exposure), підсилення (gain), формату.
- Збереження пресетів камери для кожного пристрою.

### 3. Підсистема технічного зору (Vision)
- Конвеєр обробки кадрів на OpenCV.
- Автоматична детекція країв для вирівнювання заготовки.
- Визначення кута за контуром, лінією або дугою/колом.
- Ручні інструменти: вибір ROI (області інтересу) та ручний вибір лінії.
- Оцінка достовірності (confidence score) результату детекції.

### 4. Калібрування
- Калібрування камери за шаховою дошкою (checkerboard) або Charuco.
- Калібрування піксель-в-мм.
- Корекція дисторсії.
- Зберігання калібрування окремо для кожної камери/профілю.

### 5. Керування рухом (Motion control)
- Серійне з'єднання з GRBL та PI_GRBL_HAL.
- Джогінг по осях X/Y/Z.
- Home, встановлення нуля, увімкнення/вимкнення шпинделя.
- Програмні (soft) ліміти та watchdog з'єднання.

### 6. Карта висот (Height map)
- Сканування сітки та збереження даних поверхні Z.
- Експорт карти висот у файл.
- Візуалізація карти як теплової карти (heatmap).
- Використання карти для компенсації по Z.

### 7. Автоматизація
- Асистоване позиціонування (assisted positioning workflow).
- Сценарій сканування деталі, більшої за поле зору камери.
- Автоматичний та ручний режим переміщення камери.
- Макро-дії для типових операцій налаштування.

### 8. Дані та збереження
- Збереження налаштувань, профілів, калібровок і даних завдань.
- Експорт/імпорт конфігурації.
- Спочатку JSON, за потреби пізніше — SQLite.

### 9. Майбутні покращення
- Підтримка кількох камер одночасно.
- Пошук за шаблоном (template matching) та AI-детекція.
- Анотації вимірювань і звітність.
- Підтримка IP-камер/RTSP.
- Попередній перегляд траєкторії інструменту та асистент вирівнювання деталі.

## Примітки
- Цей файл навмисно редагований і призначений для редагування.
- Нові вимоги додавати сюди в міру розвитку проєкту.
- Код застосунку має залишатися узгодженим із цим планом.
- **Ключове правило для агента коду:** будь-яка нова форма/вікно/діалог створюється як окремий `.ui`-файл у `ui/`, а не вбудовується в Python-код. Порушення цього правила вважати помилкою реалізації.

## Поточний статус реалізації (Python/PySide6)
- Проєкт перейшов на Python/PySide6 + Qt Designer. UI завантажується через `QUiLoader` із `.ui` файлів.
- Підтримка камер тепер використовує DirectShow/MSMF/ANY backends для Windows.
- Налаштування камери (ширина/висота/FPS/exposure/gain) тепер зберігаються у [data/camera_presets.json](D:/STM32PLC/ProbeCAM CNC/data/camera_presets.json) і підвантажуються під час запуску.
- Для швидкої перевірки доступності камер додано [check_cameras.py](D:/STM32PLC/ProbeCAM CNC/check_cameras.py).
